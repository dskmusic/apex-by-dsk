# Design decisions

| # | Topic | Decision | Why |
|---|-------|----------|-----|
| 1 | Origin | Built on the Genesix / Infinitum code base (GPLv3, namespace `gx`): theme, widgets, preset library, tooling, scripts, CI. Neither project is modified. | Same quality, same look, less new code. |
| 2 | Plugin codes | Manufacturer `Dskm`, plugin `Apex`, bundle `com.dskmusic.apex` | Frozen forever (DAW session compatibility). |
| 3 | Repo visibility | Private until the first release; GitHub Actions **disabled at repo level** (workflows are the final public ones) | Private-repo Actions minutes are metered. One API call enables everything on the day it goes public. No public binaries while private (GPLv3: binaries must ship with source). |
| 4 | Commit e-mail | Repo-local GitHub noreply address from the first commit | The history becomes public when the repo is flipped. |
| 5 | Installer | New Inno Setup AppId | Must not upgrade or uninstall Genesix / Infinitum. |
| 6 | Export formats | WAV 24-bit, FLAC, OGG (JUCE built-in); no MP3 | No extra encoder code or dependency. |
| 7 | Synthesis, no samples | Every effect is a pure function of (parameters, seed, sample rate): `renderFx()` | Always different, tiny download, bit-exact bounces. |
| 8 | Offline rendering | A background thread renders the whole effect after parameter changes (120 ms debounce); the audio thread only plays finished buffers | Heavy synthesis never touches the audio thread; playback equals the offline render bit for bit (tested). |
| 9 | Trigger waits for the render | A trigger issued after a parameter change waits (max 5 s) until the new sound is rendered | Pressing Play right after GENERATE never plays the previous effect. |
| 10 | Duration semantics | `Duration` = start of the build -> Hit Point (the climax lands exactly there); `Head` = silence before; `Tail` = after the hit | Matches an editor's mental model: place the clip so the hit meets the cut. |
| 11 | Beats / frames | Beats use the host tempo (fallback BPM parameter); frames use 24 / 25 / 30 / 60 fps | Durations stay musical or frame-accurate. |
| 12 | Host timeline lock | Optional: position = host PPQ - start beat, so DAW bounces match what was heard | Deterministic bounces without relying on MIDI timing. |
| 13 | MIDI variation mode | 12 pre-rendered variations (seed + pitch class x 7919), rendered in the background | A note can fire instantly without rendering on the audio thread. |
| 14 | Loudness | BS.1770-style K-weighting; the target (default -16 LUFS) applies to the loudest 3 s window (short-term max), not the integrated value; look-ahead brick-wall limiter at -1 dBFS | A long reverb tail must not make the hit quieter; the windowed-minimum average can never exceed the required gain. |
| 15 | Frozen parameter IDs | Block order in `Params.h` is frozen; new layers / parameters are appended at the end | Old sessions and presets must keep sounding the same. |
| 16 | Factory bank | 7 effects x 36 type/style pairs = 252, generated by `ApexTool factory`, best-of-3 per effect, validated at 48 kHz (level, DC, NaN, clicks) and level-matched by the LUFS target | Reproducible; the test suite validates every type and style on each run. |
| 17 | Removed from Infinitum | Self-playing engine, landscapes, harmony, chord generator, video export, noise generator | Not needed by a one-shot effect generator. |
| 18 | Visual | One GLSL fragment shader (shock waves, light streaks, anamorphic flare) with a painted CPU fallback; log in `gpu-log.txt` if the shader fails | Cinematic look at almost no code; never a blank view. |
| 19 | Installer AppId | Fresh GUID (not Infinitum's, not Genesix's) | Installing Apex must never upgrade or uninstall another DSK plugin. |
| 20 | Triggers vs. rendering | A buffer is playable only if it matches the current parameters and the sample rate; offline bounces render synchronously inside `processBlock`, real-time note-ons wait (max 5 s) for the background render | Bounces never drop or mis-play an effect, even if you bounce right after opening the project. |
